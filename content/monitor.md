# 数据外传监控六机制

一句话：规则管「单次工具调用」，机制管「整台机器」。六件事合起来回答一个问题：这台电脑上的 AI 工具，有没有把你的东西带走。

## 为什么单靠规则不够

{{facts.F-001.value.rules}} 条规则拦的是**动作**：这次调用读了什么、写了哪、连了谁。它拦不到三类情况：

1. 动作发生在钩子装上之前。
2. 动作发生在钩子之外（工具的更新程序、后台服务、另一个没登记的客户端）。
3. 动作本身合规，但结果是外传（打包上传用的是正常网络请求）。

这三类只能靠「翻工具自己留下的痕迹」和「看机器此刻在往外连什么」来答。这就是六机制。

## 六机制总表

| 机制 | 回答的问题 | 命令 |
|---|---|---|
| 自认审计 | AI 工具有没有外传痕迹 | `antinel host-scan`／`antinel host-audit` |
| 出口账本 | 此刻谁在往外发 | `antinel egress` |
| 宿主拦截 | 外传落点能不能当场拦下 | `antinel host-shield` |
| 源码金丝雀 | 代码有没有被带出去 | `antinel canary` |
| 安全区 | 整体收紧外传口径 | `antinel settings set net_mode block`／`antinel zone add` |
| 报告呈现 | 结果怎么交差 | `antinel ui`／`brief`／`digest`／`inbox` |

## 一、自认审计

```
antinel host-scan
antinel host-audit
```

`host-scan` 全机盘点，只读，约一到两分钟：你电脑上装了哪些 AI 工具、各自什么版本、有没有留下外传痕迹。`host-audit` 只看今天，回答「这些工具今天有没有出格举动」。

「自认」两个字是刻意的：监理读的是**工具自己写下的字段**——它自己记的「上次上传时间」「打包后体积」。这不是我们亲眼看见的动作，所以我们说「自认」，不说「已确认」。

覆盖范围是登记表里的 {{facts.F-003.value.hosts}} 类宿主。**没被列出来的工具不等于安全**，只等于监理没有它的取证路径。

## 二、出口账本

```
antinel egress
```

每约 30 秒采样一次系统网络连接表，只记录 AI 工具进程的对外连接：进程名、PID、远端地址、协议、时间。**不记载荷**——不抓包，不看内容。

口径很重要：**有连接不等于有问题**。打包上传是长时间大流量的连接，正常问答是短连接。账本只给事实，判断权在你。

## 三、宿主拦截

```
antinel host-shield status
antinel host-shield enable
antinel host-shield queue
antinel host-shield decide "<路径>" allow_always
```

对已登记的外传落点（典型是工具自己的「待上传快照」目录）施加写拒绝。默认关闭，需要你主动布防。

`queue` 看等你表态的落点，`decide` 决定放行或拒绝。**放行必须你本人在终端操作**——Agent 不能替你签字。这一条是硬约束，不是建议。

## 四、源码金丝雀

```
antinel canary plant
antinel canary list
```

在你项目里埋一个标记文件。任何人读到它，SEC-11 会提醒并记账。如果这个标记出现在工具的输出里、日志里、或者某次上传的内容里，那就是外传的证据。

金丝雀的好处是它**不依赖你信任任何一方**。你不需要相信工具没上传，只需要看标记有没有跑出去。

## 五、安全区

```
antinel settings set net_mode block
antinel zone add <目录>
```

把外传口径整体切到拦截，并按目录划定安全区，区内的写行为受控。安全区清单本身进审计链——改过就有记录。

这是六机制里唯一会**主动收紧**动作的一个，其余五个都是观测与取证。

## 六、报告呈现

```
antinel ui
antinel brief
antinel digest --days 1
antinel inbox report
```

结果必须能交差。`ui` 在本机浏览器里给一个能点的页面，`brief` 给一页纸，`digest` 给时间线，`inbox` 给待处理项。

六机制的输出都落在同一套证据口径上，翻成六档裁决——见[六档裁决](/verdicts/)。这一层最容易出错的地方是措辞：「查过没发现」和「没查到」必须长得不一样。体检页怎么做这件事，写在[安全体检](/checkup/)。

## 六机制不做什么

- 不抓包，不读载荷，不做流量还原。
- 不上传任何数据。六机制全部在本机跑完。
- 不给人做效率排名，只记 Agent 的行为与消耗。
- 不承诺覆盖未登记的工具。
