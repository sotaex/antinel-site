# 品牌与用词

一句话：名字写错，读者会以为这是另一个东西。这一页把该用的写法和不该用的说法一次说清，谁引用都照这个来。

## 名字

| 场合 | 写法 | 备注 |
|---|---|---|
| 中文全称 | Antinel 监理 | 第一次出现用全称，之后可以只写「监理」 |
| 英文名 | Antinel Steward | 海外用这个，不要音译 |
| 命令名 | `antinel` | 全小写，不加连字符 |
| PyPI 包名 | `antinel` | **不是** `antinel-security` |
| MCP 服务名 | `io.github.sotaex/agentstate` | 保持原样，不要改写 |
| 代码仓 | `sotaex/agentstate` | 同上 |

## 不要用的词

| 别写 | 为什么 | 改写成 |
|---|---|---|
| 哨兵 | 哨兵只喊不记。我们的价值一半在留痕 | 监理 |
| 杀毒／防病毒 | 看的东西不一样，会被当成杀毒软件来评价 | 监理；需要对比时说「不同于杀毒」 |
| 防火墙 | 我们没有网络隔离能力 | 护栏 |
| 沙箱 | 我们不提供隔离 | 护栏；需要对比时见[和谁不一样](/compare/) |
| 认证／认证通过 | 我们不卖标识，也没有认证资质 | 裁决；说清是哪一档 |
| 100% 防护／绝对安全 | 拦不住的东西写在[边界](/threat-model/)里 | 说明拦什么、不拦什么 |
| 检测报告 | 不是持证机构出的 | 审计与安全评估 |

## 三句话不许省

对外说结论时，这三句必须跟着：

1. **「自认」**——结论来自工具自己写下的字段，不是我们亲眼看见的动作。
2. **「没发现 ≠ 没有」**——⚪ 查过没发现记录，不等于清白。
3. **「没查到 ≠ 没问题」**——⚫ 没查到是盲区，必须单独报数。

省掉任何一句，读者就会把「没查到」读成「安全」。这是我们最不能犯的错。

## 数字怎么写

- 说规则数就说「{{facts.F-001.value.rules}} 条」，说类别就说「{{facts.F-001.value.categories}} 类」，说门就说「{{facts.F-001.value.gates}} 道」。这三个数不要混着用。
- 说宿主覆盖就说「{{facts.F-003.value.hosts}} 类」，并且紧跟一句「没被列出来的工具不等于安全」。
- 版本号只有一个当前值：**{{product_version}}**。引用旧版本要标明「旧版」，不要拿旧版数字当现状。
- 百分比能不用就不用。要说得清，就写「几处 / 总共几处」。

## 中文行文

- 中英文之间加一个空格：`pip 包 antinel`，不是 `pip包antinel`。
- 命令与字段名一律用等宽字体包起来：`antinel verify`。
- 不用感叹号，不用「震撼」「颠覆」「革命性」这类词。
- 讲机制就说机制，不讲愿景。读者要判断的是「它怎么做到的」，不是「它想成为什么」。

## 引用格式

转载或引用本站结论时，按这个格式署名：

```
Antinel 监理 · <页面标题> · 产品版本 <版本> · <URL>
```

页脚给了标准引用块，直接复制即可。许可条款见[许可与中立](/license/)。
