# 威胁模型与边界

一句话：监理是护栏，不是隔离层。这一页把「拦什么、不拦什么、为什么」写清楚——写下来的边界，比藏起来的自信安全。

## 假设的对手是谁

三种，按现实程度排序：

1. **工具本身出格**：AI 编程工具为了「把活干完」越界。它读了不该读的文件，把项目打包发去了某个服务端，在项目外写了配置。
2. **第三方内容投毒**：你装的技能包、MCP 服务器、提示模板里藏了指令，或者藏了看不见的字符。
3. **供应链撞名**：装包时名字差一个字母，装进来的东西和你想的不一样。

三种共同点：**都不是病毒**。没有恶意二进制，没有提权漏洞，只有「合规性」问题——动作本身合法，但它不该发生。

## 拦什么

{{facts.F-001.value.rules}} 条规则，分四道门。逐条见[规则目录](/rules/)，门的分法见[四道门](/gates/)。概括说：

- 读密钥类文件、把密钥写进内容、读剪贴板／聊天记录／输入法词库。
- 删除、写到项目外、改终端启动配置、设开机自启、写备用数据流、破坏权限属主。
- 访问白名单外域名、代码里内置联网、命令里出现陌生域名、建隐蔽出网通道。
- 技能文件藏注入指令、隐形字符、超长编码载荷、解码后立即执行。
- 技能名与目录不符、MCP 配置被改动／含明文密钥／指向远程服务器／工具描述投毒、装撞名包。

## 不拦什么

这一节是这一页的重点。

**一、不解析脚本内容。** 钩子只看工具调用的文本：命令行长什么样、要读哪个文件、要连哪个域名。把危险操作写进脚本文件再执行，钩子看到的是「运行一个脚本」，拦不住。会有记录和告警（`dst02_bash_path_suspect`），但不会阻止执行。

**二、不承诺沙箱级隔离。** 要隔离，用容器或虚拟机。这两件事不冲突，也不互相替代：容器管「它进不来」，监理管「它做了什么都记着、该停的当场停」。

**三、备用数据流只拦写入。** Windows 的 ADS（`文件:流名`）能拦写入路径，流里的内容读不回来。

**四、输出不是检验检测报告。** 我们出具的是一份审计与安全评估，不是第三方检测机构报告。这句话写在[许可页](/license/)，不含糊。

**五、不能替代内核级防护。** 钩子是宿主的一个回调，宿主不调它，它就不在。宿主改了协议，或者工具绕开宿主直接跑，钩子就看不到。

## 运行时性质

| 性质 | 值 | 意义 |
|---|---|---|
| 运行时联网 | {{facts.F-005.value.network}} | 一个要向云端汇报的监理，没法向本地业主负责 |
| 依赖 | 纯标准库（{{facts.F-005.value.stdlib_only}}） | 不会被自己的依赖链带进新的供应链风险 |
| 常驻进程 | {{facts.F-005.value.daemon}} | 不占后台，不偷偷跑，关机就没了。开启宿主拦截（`antinel host-shield enable`）后会有一个：登录触发，只在本机跑，不联网 |
| 单次钩子时延 | 约 {{facts.F-004.value.p50_ms}} ms | Windows 上解释器启动占主导；Linux／macOS 未测 |

时延这一项只测了 Windows。写「未测」比写一个好看的数诚实。

## 两个已知的失败模式

**审计写失败默认放行。** 磁盘满、权限不对的时候，写不进审计链。这时候我们的选择是**放行并让它可见**（`AUDIT_WRITE_FAILED`），而不是拦下所有动作。理由是：拦死会让整台机器不能用，而用户并不知道发生了什么。要改成拦死，可以置 `fail_closed_on_audit_loss`——但那要你自己决定。

**钩子降级到回退规则。** 规则文件读不出来的时候，钩子会降级到一小批回退规则（`rules_integrity_fallback`），并记账。降级期间拦截能力显著下降，所以这条信号出现时应该重跑安装。

## 白名单不得放宽严重级

策略里可以加白名单、放行域名、加项目路径。有一条红线不动：**白名单不得放宽严重级拦截**。

原因很直接：能放宽严重级的话，「白名单」就成了绕过所有规则的开关。要放行某一次拦截，走 `host-shield decide` 并留下记录，而不是改规则。

## 三条我们不做的承诺

1. 不承诺「装了就不会被偷数据」。承诺的是「被偷了会留痕，且你能复算」。
2. 不承诺覆盖所有工具。登记表里是 {{facts.F-003.value.hosts}} 类宿主，之外的工具我们不知道它把痕迹写在哪。
3. 不承诺判定永远正确。所以审计链只增不删、判据公开，第三方复跑可以取代随包判定。见[审计链与复算](/audit/)。
