# 审计链与复算

一句话：别信我们。审计链只增不删、每条带可重算摘要、判据公开。任何人复跑出不同结论，就以他的为准。

## 链长什么样

每一条记录带一个摘要：

```
hash(n) = sha256( hash(n-1) + 本条规范化 JSON )
```

改一个字节，从那一条起后面全部对不上。这就是「不可事后篡改」的具体含义——不是「我们保证不改」，是「改了能被算出来」。

验证：

```
antinel verify
```

退出码 0＝链干净。非 0 就说明中间有断点或改动。

## 只增不删

审计链是追加式台账。清理只按日期滚动（保留天数可配），滚动本身也记账：删了哪些日期、删了几条。

有两种失败模式会被显式记录，而不是悄悄吞掉：

- **写失败**：记 `AUDIT_WRITE_FAILED`，默认放行且可见（原因见[威胁模型](/threat-model/)）。
- **丢条**：补偿写入没赶上的记录，跨进程记在 `lost.json` 里，下次补。

「记不下来」和「没发生」必须能分开，否则台账就只是一份好看的日志。

## 第三方复跑

```
python -m scripts.run_harness
```

复跑全部断言，得到你自己的结论，写进 `psl/judgment.json`。**任何人复跑出不同结论，即取代随包判定**——追加式，原记录不删不改。

这一条是整个信任模型的支点。我们不要求你相信随包的结论，只要求你在不同意时能留下自己的结论。系统必须认它。

## 亲眼看它怎么被改坏

```
python challenge/verify.py
python challenge/tamper.py
python challenge/tamper-lab.html
```

第一条：独立复算，不依赖本包。第二条：改一条记录、复算、报 tamper。第三条：在浏览器里手动改，看它当场报错。

这三个脚本存在的意义是：让「不可篡改」从一句声明变成你可以自己动手验证的事。

## 执法有效性自检

```
python -m tools.enforce_probe
```

合成一个必拦事件，跑真钩子，断言所有下发通道都收到了。

**探针通过 ≠ 宿主在岗。** 探针证明「钩子有能力拦」，不证明「宿主正在调钩子」。在岗证据只认审计链上的真实流量记录。这两类证据分开记账，不合并成一句「运行正常」。

## 复算的三个层次

| 层次 | 你复算什么 | 需要什么 |
|---|---|---|
| 一 | 链有没有被动过 | 装好的包，一条 `antinel verify` |
| 二 | 随包结论对不对 | 复跑断言，得到自己的 verdict |
| 三 | 判据本身合不合理 | 读规则文件，自己写一条判据替换它 |

第三层是最终目的：判据写在 `rules/default.json` 里，格式是公开的。你要是觉得某条规则判得太松或太紧，改它，然后复算——不需要我们的许可。
